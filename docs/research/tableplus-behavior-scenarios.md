# Skenario evaluasi perilaku TablePlus dan Tabler

Jalankan aksi yang sama pada dua aplikasi dengan fixture, driver, dan pengaturan yang sebanding. Catat apa yang terjadi sejak aksi dipicu sampai pengguna dapat melanjutkan kerja. Untuk aksi yang dapat menulis data, periksa kondisi database dari sesi lain.

Gunakan [spesifikasi TablePlus](tableplus-functional-spec.md) untuk menemukan variasi menu, opsi per driver, dan referensi historis. Gunakan [checklist QA macOS Tabler](../qa-macos.md) untuk pemeriksaan implementasi. Skenario di bawah menetapkan langkah dan kriteria evaluasi. [Catatan macOS 11 November 2026](tableplus-macos-2026-11-11.md) berisi hasil pengujian awal.

## Persiapan

Untuk pengujian macOS pertama, jalankan dari root repo. Setiap aplikasi mendapat salinan SQLite tersendiri. Gunakan salinan baru dari `seed.sqlite` untuk skenario yang mengubah data atau schema, setelah menutup koneksi ke salinan sebelumnya.

```sh
parity_dir=$(mktemp -d "${TMPDIR:-/tmp}/tabler-parity.XXXXXX")
TABLER_TEST_SQLITE_PATH="$parity_dir/seed.sqlite" sh dev/scripts/build-sqlite.sh
cp "$parity_dir/seed.sqlite" "$parity_dir/tableplus.sqlite"
cp "$parity_dir/seed.sqlite" "$parity_dir/tabler.sqlite"
printf '%s\n' "$parity_dir"
```

Pada Windows, salin `seed.sqlite` yang sama dari hasil build, atau buat dengan SQLite CLI dari `dev/seed/sqlite/seed.sql`. Untuk PostgreSQL dan MySQL/MariaDB, siapkan layanan dan seed sesuai [panduan database pengembangan](../../dev/README.md). Jalankan pada instance pengujian. Pulihkan seed di antara aplikasi atau gunakan dua instance dengan data awal yang identik. Siapkan akun dengan izin baca saja untuk `SAFE-02` dan akun admin fixture untuk `ADMIN`.

Gunakan `users` untuk edit dan nilai bertipe, `posts` untuk foreign key, `post_tags` untuk primary key gabungan, `audit_log` untuk tabel tanpa primary key, `events_big` untuk 100.000 baris, serta `"Order Items"` dan `"CamelCase"` untuk identifier yang perlu quoting. SQL dalam tabel memakai sintaks SQLite/PostgreSQL. Gunakan backtick untuk identifier MySQL yang perlu quoting.

Periksa perubahan dari koneksi terpisah. Contoh pemeriksaan ini memperlihatkan nilai awal dan membantu mendeteksi perubahan yang sudah tersimpan sebelum atau sesudah commit. Pakai berkas aplikasi yang sedang diuji.

```sh
sqlite3 -readonly "$parity_dir/tableplus.sqlite" \
  'SELECT id, name, email, quote(nickname), big_id FROM users WHERE id IN (1, 2) ORDER BY id;'
```

## Cara mencatat hasil

- Catat tanggal, OS, versi dan build kedua aplikasi, commit dan perubahan lokal Tabler, driver dan versi server, fixture, mode lisensi bila memengaruhi akses, dan pengaturan yang berbeda dari default. Tandai apakah Tabler dijalankan sebagai aplikasi native atau melalui `pnpm dev:mock`.
- Untuk setiap ID, catat keadaan awal, aksi melalui menu atau keyboard, kontrol yang menerima input, keadaan sesudah aksi, serta perbedaan klik dan shortcut bila ada. Catat label, urutan dialog, fokus, seleksi, tab atau database aktif, draft, dan pesan yang memengaruhi langkah berikutnya. Tambahkan tangkapan layar atau rekaman bertimestamp jika membantu. Gunakan koneksi fixture agar host dan kredensial pribadi tidak ikut terekam.
- Isi status bukti TablePlus sebagai `diamati`, `terdokumentasi`, atau `belum diuji`. Isi hasil Tabler sebagai `sesuai`, `berbeda`, `belum dibandingkan`, atau `tidak berlaku` disertai alasannya. Kesimpulan `sesuai` atau `berbeda` memerlukan aksi yang dijalankan di kedua aplikasi dengan kondisi yang sebanding. Catat perilaku TablePlus yang diamati meskipun berbeda dari kriteria keamanan Tabler.
- Untuk `berbeda`, tulis dampaknya bagi pengguna dan langkah terkecil untuk mereproduksi. Pisahkan perbedaan label dari perbedaan cakupan aksi, perubahan database, dan hilangnya draft. Jika aplikasi gagal, rekam pesan, efek samping, dan apakah percobaan berikutnya dapat dilanjutkan.

`P0` mencakup alur harian dan risiko perubahan data. `P1` mencakup alur rutin, kasus tepi, dan pemulihan. `P2` mencakup kebutuhan khusus atau integrasi opsional. Jalankan `P0` SQLite native di macOS terlebih dahulu. Lanjutkan dengan PostgreSQL dan MySQL/MariaDB untuk transaksi, koneksi server, tipe native, hak akses, dan pembatalan. Ulangi `P0` serta skenario jendela, shortcut, dan dialog file pada Windows. Gunakan menu aplikasi di setiap OS untuk menemukan shortcut yang benar, lalu jalankan dari fokus grid, editor, dan dialog. Untuk driver lain, pilih skenario berdasarkan operasi yang didukung driver tersebut dan catat padanannya.
